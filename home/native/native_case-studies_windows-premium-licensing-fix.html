The client and the problem

Ecom Swift LLC publishes a portfolio of Windows desktop apps through the Microsoft Store, monetised with Premium add-ons (monthly, yearly, lifetime). On 13 November 2026 a customer bought the yearly Premium plan for MalwareEnemy, our malware-scanning utility. The purchase completed and the order existed in Microsoft's records, yet the app, after "Restore purchase", reported that no active Premium purchase could be found.

A paying customer locked out of what they bought is the most damaging bug a small publisher can ship: it is a refund, a one-star review and a support thread at once. The first email arrived with only the symptom and an order receipt.

What we did with Claude

Triage

Read the customer's message, the order record and the app's entitlement code together, and listed ranked hypotheses: add-on licence list incomplete for subscriptions, paying Microsoft account different from the signed-in one, or the Store outage reported the same day.

Root cause

Traced the check to a PowerShell call that read only GetAppLicenseAsync().AddOnLicenses. Microsoft Q&A threads document that this list can omit subscription add-ons. Claude identified this as the probable cause and said what it could not confirm without the customer's machine.

Fix

Wrote version 1.1.1: the app now also reads the Store's owned-products collection (GetUserCollectionAsync, durable type), and either source unlocks Premium. Rules for ended or placeholder expiry dates (the Store reports 1601-01-01 for "no end date") were moved into a small pure module so they can be unit tested without Electron or Windows.

Make the next case solvable

Added Settings, About, "Copy support info", which gives a customer one click to send exactly what the Store reported, so the next report arrives with evidence instead of guesses.

Audit the portfolio

Instead of closing the ticket, Claude searched all other Windows apps for the same pattern. All 25 (21 Electron, 4 .NET) used the same single-source check. Claude ported the fix to each and pushed to version control, with no store submission until each is reviewed.
